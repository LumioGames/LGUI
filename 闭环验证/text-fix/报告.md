# 文本 Inspector 最小修复

已在固定网页编辑器 `45f0bef93bb16d507552b673ace6d5af417a8a0f` 的本地 clone 上修复。Core/functions/backend 均保持网页原来的 `0.2.4`，没有升级依赖、提交或推送。工程仍为此次自制的 `验证/toolchain-test/project/Inventory.fairy`，回归仅读入该工程并在内存应用事务。

## 原因与改动

`InspectorController.createDisplayNodeCommand` 以前同时提交 `props.text/font/fontSize/color` 单字段和包含相同信息的 `props.textProperties`。真实 Core 0.2.4 预检明确拒绝这两种口径混用，错误为 `invalid_display_node_payload: textProperties cannot be combined with individual text property overrides`。

最小修复只删除四个重复的单字段赋值，沿用已有完整 `textProperties` 构造和“确有改动才写入”的比较。文案、字体、字号、颜色以及对齐、间距、粗斜体、下划线等已有属性继续进入正式事务。没有放宽 Core 校验，也没有删除或绕开 preflight。

既有 `verify-inspector-host-layouts.mjs` 原先断言重复的四字段必须存在，等于锁定非法行为。本轮在主 agent 明确授权后，仅把相关四行断言改为检查 `props.textProperties` 内对应值；新回归则把真实 Inspector 产生的命令交给真实 Core，防止只测试错误的自有快照。

## 撤销检查

读取生产 `createInverseSetDisplayNodePropsOperation` 后，用红灯保存的真实旧命令、绿灯保存的新命令分别生成逆操作。旧命令会生成同样非法的 `text + textProperties` 逆操作；但旧前向事务已被拒绝，正常live路径不会把它成功写进撤销历史。

新命令只提交 `textProperties`，生产逆生成器也只生成同一完整组。真实 Core 完成前向apply、逆操作preflight、逆操作apply，文案恢复为原值“旅者背包 · Agent 已编辑”。没有发现合法新Inspector命令需要另改Adapter的撤销缺陷。按分工未修改 `EditorCommandAdapter.ts` 或 `BrowserLiveSessionBridge.ts`。

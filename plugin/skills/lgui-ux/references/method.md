# 做法：原型图 → UX 设计稿

每次照这个顺序做。字段怎么写见 [design-json.md](design-json.md)。文档里的 `lgui xxx` 指 `node <插件目录>/tools/lgui.mjs xxx`。

设计稿要回答三件事：图上有什么（量出来）、图上看不出来的是什么（问出来）、哪些已经有现成的（查出来）。怎么拼、怎么写代码不在设计稿里，那是 `lgui-ui`、`lgui-code` 和规范的事。

## 1. 开始前：读配置，问用户

**读：** 在工程里就读 `.lgui/project.json`：`orientation`、`designSize`、`languages`、`defaultLanguage`、`verifySizes`。这些不用问，`lgui ux page` 也会自己读。还没有工程就问，问到的答案以后就是建工程的配置。

**问**（一次问完，用户说「你定」就自己定，并记进未定事项、`owner` 写 `agent`）：

| 问什么 | 影响什么 |
|---|---|
| 原型图是不是自己的作品 | 不是：角色、名字、图案全部换成原创的，文字的替换记进 `renames`（和原文差不多宽） |
| 只出设计稿，还是连开发交接一起 | `mode`：`design` 或 `full` |
| 只出网页，还是也导出 Unity | `platforms`：导出 Unity 时不能用代码图标 |
| 只有触屏，还是也有键盘鼠标 | `inputs`：有键盘鼠标时按钮多一个悬停状态，全屏界面底部留 64 给操作提示栏 |
| 图里没有的画面（点开的弹窗等）要不要设计 | 不要：只记一条入口（`"designed": false`） |
| 美术谁出（AI、美术、已有素材） | 资源的 `by`；AI 出图才需要图集分页 |

原型图只有一个方向、工程两个方向都支持时，告诉用户另一个方向会由你设计、需要他看线框确认。

## 2. 定换算比例

设计单位 = 原图像素 × `scale`，`scale` = 设计尺寸的短边 ÷ 原图的短边（原图宽 900、设计宽 1080 就是 1.2）。量的时候 `lgui ux crop` 带上 `--scale`，网格标出来的直接是设计单位，不用自己乘。

原图比例和设计尺寸不一样时（原图 9:20、设计尺寸 9:16）：已有别的界面的工程不改设计尺寸，贴上下边的元素保持到边的距离，中间的内容吸收差值；新工程可以把设计尺寸改成原图的比例。`lgui ux page` 会提醒。

## 3. 量

1. **先整图看一遍：** `lgui ux crop <图> --scale <比例>`，分出区域（顶栏、侧栏、主体、底栏……每张图不一样，按图分）。
2. **每个区域放大：** `--rect x,y,宽,高`（原图像素），读出每个元素的外框。
3. **每类部件再放大 3 倍以上：** 读内部结构（图标、文字、角标各在哪）、圆角、文字的字号和描边。
4. **颜色看命令打印的主色**，不要凭眼睛估。文字颜色、描边颜色、底色分别在只含它的小块上取。

量不准的（被别的东西挡住、半透明）标成 `estimated`。一次量准，位置只存一份。

## 4. 拆元素、编号

- 按区域给编号前缀（比如顶栏 T01、T02…），前缀自己定，一张图里别重复。编号定了就不改：资源、用例都靠它对上。
- 一个元素 = 一个以后要单独放、单独绑定、或单独出图的东西。纯装饰的并进所属元素的说明里。
- 层叠顺序 = `elements` 里的顺序（后面的在上面）。
- **重复的结构只定义一次：** 同一种东西出现两次以上（三个货币栏、一列活动入口）就在 `components` 里定义一次，零件的位置相对组件写；每个出现的地方是一个实例（元素写 `component`）。

## 5. 判断每个元素做什么

图上的视觉线索能推出类型和行为。下表是通用线索，右边是该先想到的现成做法（写进 `reuse` 或 `uses` 前，在规范里确认它存在）：

| 图上看到 | 多半是 | 先考虑 |
|---|---|---|
| 角标、小红点、「!」 | 有提醒状态 | 子控件 `redDot`，`Common/RedDot` 换样子 |
| 居中面板 + 标题 + 关闭 | 弹窗 | 排布模式 `dialog`；只是二次确认用 `lgui.confirm`（`Common/Confirm` 换样子） |
| 重复的格子、条目 | 列表 | 列表 + 子项组件，排布模式 `grid` 或 `split` |
| 一排页签，其中一个突出 | 页签切换 | 排布模式 `tabs`，控制器 |
| 资源图标 + 数字 + 加号 | 货币栏，点了去购买 | 一个组件多个实例 |
| 带「万」「K」的数字 | 缩写的数字 | `format.compact` |
| 会涨会跌的数字 | 数值变化要滚动 | 绑定词 `roll` |
| 在走的时间 | 倒计时 | 绑定词 `tick` + `format.duration` |
| 进度条 + 百分比 | 进度 | 进度条组件，绑定词 `progress` |
| 一排小圆点，其中一个亮 | 轮播、翻页 | 控制器 |
| 按钮上的消耗数字（图标 + ×5） | 点了要扣资源，不够要提示 | `lgui.toast` |
| 美术风格的数字（伤害、连击） | 美术字 | `Common/ArtText` |
| 开关、单选、勾选 | 用户改的值 | Check / Radio 按钮，绑定词 `selected` |
| 飘出来的一句提示、转圈 | 提示、加载中 | `lgui.toast`、`lgui.loading` |
| 箭头、加号、关闭这类简单图形 | 图标 | 代码图标（只在网页端能用，要导出 Unity 就出图） |

推不出来的（一个没有文字的图标、看不出点了去哪）不要编：`action` 留空，记一条未定事项问用户。

每个元素写：点了做什么（`action`、`opens`）、有哪些状态（`states`：叫什么、长什么样、什么时候）、绑什么数据（`data`）。弹窗里关闭它的元素写 `"closes": true`。列表写能不能滚、最少最多几项。

## 6. 定做不做（用户定）

每个元素标 `scope`：`full` 完整实现（有逻辑、要测）、`stub` 占位（外观做出来，点了给统一的提示）、`display` 只显示。你先给建议：主流程 `full`，外围入口 `stub`。然后**停下来给用户看原型页确认**（第 12 步）。

## 7. 标复用来源

先运行 `lgui ui list --shared`（工程里现成的），再读 UI 开发规范第 7.4 节（排布模式）、第 10 节（Common 包），MVC 开发规范第 6.4 节（绑定词）、第 11 节（常用工具）。然后给每个要做成组件的元素、每个组件、每项资源写 `reuse`：

| `from` | 意思 | 例子 |
|---|---|---|
| `framework` | 框架自带，直接用 | `Common/Toast` |
| `reskin` | 框架自带，换样子（名字和必有控件不能动） | `Common/RedDot` 改成图上的样式 |
| `pattern` | 整个画面从排布模式生成 | `dialog` |
| `project` | 工程里已经有的 | `Common/CurrencyBar` |
| `new` | 以上都不是，新做 | 同一个新组件两个以上画面要用就写 `"to": "Common"` |
| `none` | 不需要组件（纯文字、纯图片） | — |

框架的行为（数字缩写、滚动、倒计时……）写进 `uses`。写的名字不存在时 `lgui ux page` 报错。清单每次现查，不要凭记忆写。

图片也一样：同一张图多处用只登记一项；能用代码做的状态不出图（置灰、按下缩小、选中放大）；同一个物件大小不同只出最大的。

## 8. 文字

每段文字写内容、字号、颜色、描边、投影、对齐，都是设计单位，照图量。另外：

- **超长怎么办必填**（`overflow`）：`shrink` 缩字（按钮标题、短标签）、`ellipsis` 省略号（名字）、`height` 换行（说明）、`both` 框跟着变大（只用于确定不会超长的数字）。
- 会变的文字（数字、名字）写 `"dynamic": true`，内容写图上当时的样子。
- 字在图片里的写 `"image": true`，并在资源里登记成 `textImage`。
- **框架的上限会被校验：** 字号不小于 20；描边粗细加投影偏移不超过字号的 7.5%（网页和 Unity 都画不出更粗的）。原型图超了就不照抄，给用户三个选择：减细、用美术字、做成带字图片，记进未定事项。

## 9. 另一个方向

工程锁定一个方向：只出这一个方向；每个顶层元素写 `anchor`（贴哪边），屏幕比设计尺寸宽或高时多出来的空间靠它分。背景这类要画到屏幕边上的写 `"anchorTo": "screen"`，其余默认贴安全区（躲开刘海）。

工程两个方向都支持：全屏画面两个方向各一套 `rect` 和 `anchor`；弹窗只要一套，框架把它放在安全区正中。没有原型图的那个方向：

1. 先看能不能套排布模式：它们定义了横竖怎么对应（左右分栏 ↔ 上下堆叠、顶部页签 ↔ 底部页签、多列 ↔ 少列、居中弹窗 ↔ 底部弹出）。
2. 套不上就按区域重排：顶栏、侧栏、主体、底栏各自换位置，区域内部不动；组件两个方向共用。
3. 这一个方向的 `source` 全写 `designed`，给用户看线框确认。

两个方向的元素一样多、编号一样、类型一样，这是框架的硬规则（代码只写一份）。

## 10. 多语言

工程有两种以上语言时：

- `text.content` 每种语言一项。没翻译的不用编，`lgui ux page` 会按加长 40% 估。
- 看校验报的「放不下」：按中心加宽文字框、换短一点的说法、或者换排法。
- 带格式的数字各语言宽度不一样（「1.6万」和「16.3K」），按最宽的留。
- 带字图片每种语言一个版本，或者改成引擎写字。
- 字体要覆盖全部语言；原型图里那种字体有没有其他语言的字形，记进未定事项。

## 11. 资源

每张要出的图登记一项：尺寸（设计单位）、九宫格边距、圆角、放哪个包、谁出。会被拉宽拉高的（栏、按钮、面板）是九宫格，边距按图上真实的边框量，不能比圆角小。

**AI 出图时才做：** 给每项资源写 `sheet`（图集页号），同一页一起出、风格才一致。分页规则：尺寸相近的放一页（整页只有一个缩放比例，差 2.5 倍以上校验会警告）；九宫格零件和图标分开；一页不要太满。`lgui ux page` 会按 `assets` 的顺序生成每页的拆图名字文件 `art/<页号>.txt`。整页图怎么画、提示词怎么写照 UI 开发规范第 5.1 节，那里是唯一的权威。不透明的整屏效果图不要当透明物件的参考图，会把背景带进来；原型图不是自己的作品时，画角色、图案不附原型图。

## 12. 生成，给用户确认

`lgui ux page design/<名字>` 校验并生成。有错先改；警告逐条处理，处理不了的和用户确认。

然后把 `prototype.html` 给用户看，确认这几件事：元素拆得对不对；每个元素点了做什么、做不做；没把握的判断（未定事项）；另一个方向的排法；各语言放不下的文字怎么处理。用户改了就改 `design.json` 再生成，不手改生成物。

## 13. 全套模式（`mode: "full"`）

再补两样，然后重新生成：

- **行为用例 `cases`：** 把每个画面的流程写成可以检查的用例（怎么操作、应该看到什么），写明覆盖哪些元素、在哪跑：`headless`（`lgui test`）、`browser`（位置、尺寸、安全区只能在真浏览器里测）、`visual`（看截图）。每个 `full` 的元素至少一条。
- **开发交接 `handoff.md`：** 自动生成，只写这份设计特有的事实：范围、读什么、哪些用现成的、哪些要新做、流程、用例、未定事项。怎么做以各技能和规范为准，不往里加流程安排、代码骨架和框架命令。

## 完成前自己查一遍

- 每个元素的内部结构量了，不是只有外框。
- 每段文字都定了内容、字号、描边、超长怎么办。
- 图上当时的状态写全了：哪个选中、哪些有红点、列表显示几项。
- 遮挡顺序对：谁压在谁上面。
- 半透明、渐变这类量不准的标了 `estimated`。
- 原型图里没有、自己加的东西标了 `designed`。
- 原型图本身的小毛病（进度条和数字对不上之类）没有照抄，按数据画。

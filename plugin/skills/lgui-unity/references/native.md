For new UI projects use [project configuration](../../../docs/projects.md): declare the Unity project and prepare/generate/build methods, run generic `unity -- --action <action>`, then the project's `verify-unity`. Missing entries are untested. The rest of this reference applies only to the explicit inventory recipe.

Inventory sequence (all CLI calls include `--workspace <workspace>`): `build-web`, `unity-setup`, `unity -- -Action prepare`, `unity -- -Action generate`, `unity -- -Action build`. UNITY_EDITOR is the Unity executable path; it can also be passed with `-UnityEditor`. `run-fidelity.ps1` discovers the standard Hub path and the prior local install as fallbacks.

Then `unity -- -Action player -Width 1280 -Height 800 -EvidenceName <new-run-name>` or `-Action editor-auto`. For Editor only, run `node <workspace>/unity-migration/complex-inventory/fidelity/accept-unity-fidelity-focused.mjs <evidence-directory>`. For the complete suite run `node <workspace>/unity-migration/complex-inventory/fidelity/accept-unity-fidelity.mjs <evidence-directory> player --cycles 20` (use `editor` for Editor). The native file command pump is enabled only with an explicit verification directory. A regular shipped application does not expose it. Preserve logs and screenshots; quit through the verification protocol. Do not kill an unrelated Editor process.

PuerTS Core/V8 3.0.3 archives, fixed commit and before/after patch hashes are in dependencies.lock.json. Unity Packages/manifest.json points to the workspace's relative packages directory. Preserve those relationships and .meta files. Do not replace the four Object::Unbox compatibility changes with a broad unknown-version patch. See [architecture](../../../docs/architecture.md) and [third-party notices](../../../THIRD_PARTY_NOTICES.md).

Processes are hidden by default. For an explicitly requested visible interactive validation add `-ShowWindow`; hidden/minimized native windows may produce black screenshots even when business and geometry checks pass. Inspect pixels and keep visual status unverified in that case. Do not treat the report's functional status as a screenshot review.

The official Unity CLI is an optional build runner, separate from the Unity Editor binary. Read [Unity CLI support and tested invocation](../../../docs/unity-cli.md) before using it. Reuse the existing C# build method, pass the explicit project/editor paths, and inspect the build result and Player separately. Do not add Pipeline or MCP merely to run a build.

# FairyGUI 结构与 XML

输入是用户工作区内实际选择的 `.fairy` 工程。先读工程设置、目标包的 package.xml、目标组件及相似成品组件；不要推断产品目录或使用固定包 ID。此册是设计/离线格式参考，在线写入遵循 [会话协议](../../lgui-edit/references/session.md)。

## 组件与索引

组件根有设计尺寸，子节点放在 displayList。新增资源需要包索引注册，既有 ID 不变，新增 ID 在其作用域内唯一。目录名称由工程决定，view/、viewComponent/ 只是常见组织方式。下面是语法示意，数值不是通用画布：

```xml
<component size="320,180">
  <displayList>
    <text id="n_title" name="title" xy="16,16" size="288,28"
      fontSize="20" color="#ffffff" autoSize="none" text="示例标题"/>
  </displayList>
</component>
```

核对 src、pkg、fileName、ui:// 引用与真实资源，跨包资源的导出设置也要检查。不要将示意 ID 复制到现有工程。富文本内容按实际 UBB/XML 规则转义；节点名称必须与目标适配层的绑定对应。

## 控制器

区分控制器页 ID、页索引与页名。gear 的 pages 指向页 ID；不要因某个示例 ID 恰好等于索引，就把它们当成同一概念。保留已有页 ID；新设计采用连续 ID 可以减少误读，但不是重编号旧页的理由。

父组件实例的页覆写、控制器 exported 标志和多控制器配置必须按目标编辑器读回确认。不要把专用框架的按钮状态数和外观图层套到全部按钮。状态控制器与皮肤控制器可以分开，避免相互覆盖。细节见 [组件实例](component-instancing.md)。

## 九宫格与布局

资源索引的 `scale="9grid"` 和 scale9grid 区域要成对检查；改变显示 size 后重新检查资源切分。scale9grid 表示切分区域，不是任意四个固定边距。依据真实像素的装饰边、透明区与可拉伸区域选择，不能统一取边长 1/4。

图标/人物需保持设计比例；背景、框架、进度条可以按实际需要伸缩。素材原生尺寸不等于所有元素的尺寸上限。宽高关联改变尺寸，居中关联改变位置，loader 的 autoSize 可能与显式拉伸冲突。改变布局后在最小/最大目标尺寸验证。

发布图集由编辑器/发布器生成，不手改生成 atlas。大背景按实际图集预算拆包，不固定要求某个包名。离线变更后的真实校验/发布命令见 工作流；XML 合法不等于渲染正确。

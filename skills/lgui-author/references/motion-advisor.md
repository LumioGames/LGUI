# 静态界面后的独立动效阶段

本流程由 lgui-author 编排，依赖单独安装的 `ui-motion-advisor`。LGUI 安装包不包含该顾问，也不会自动安装它；仅安装 LGUI 不代表此阶段已可用。执行前从当前客户端的技能清单定位并读取其真实 SKILL.md，记录所用入口及可用的版本或内容摘要。缺失时报告依赖未满足，待用户提供可信的技能包或仓库安装来源后再执行此阶段；静态制作及可独立完成的工作可继续，不将其记为顾问已执行。

顾问是独立的看图技能，不是 LGUI CLI 子命令，也不会自动写入 FairyGUI 时间轴。此处没有可分发的安装源或锁定版本，不猜测下载地址，不把个人安装路径当作通用依赖，不复制兄弟工程或顾问的完整资料库。

## 调用范围与方案复用

- 新界面、新设计图或改变视觉主次/交互含义的区域，静态界面稳定后执行下面的两轮判定。
- 已有已审方案且动效目的、主次和交互不变时，时长、缓动、光带宽度等参数微调及实现修复直接复用方案，记录增量并只验证受影响表现；不新建顾问 agent，不重跑全页两轮分析。
- 新增入口、结果态或改变触发/取消语义时，只重审受影响区域；同构控件复用公共方案。用户明确追加或覆盖的动作记录为增量要求，不回写旧首判，也不让旧静态结论否决用户要求。

## 1. 前期仅预检可动性

参考图阶段记录需要独立控制的主体、背景、光效、文字、遮罩和锚点；必要的新素材纳入同批资产规划。已有复合图的烘焙阴影/边框须注明，不重复叠同形图层。先实现可运行的布局、字体、资源及基础输入/反馈，不在静态修复过程中展开完整动效库。仅要求静态效果图的任务止于该阶段。

## 2. 真实静态界面稳定后调用

需要判定的页面能真实渲染并操作、主要布局和资源稳定后，新建不继承制作历史的 agent，读取已安装 `ui-motion-advisor` 的两轮独立判定流程。Codex 使用 `fork_turns="none"`；其他客户端使用等价的隔离上下文机制，不支持时明确报告独立判定未执行。首轮只交本页设计图、用户原始要求与显式约束，保存视觉首判后返回。随后向同一agent派发交互复查：独立追踪入口发现、操作、反馈、状态变化与退出，补漏后合并。已确认交互事实在第二轮按来源补充；调用方推断的用途、频率与语义不当作既定事实。

调用方不预告哪些区域静态/应该动、不限制为微动，也不传制作聊天、旧参数、旧方案/评分、失败点或期望答案。首轮不看实现截图、代码或节点清单；真实截图与平台能力留到合并后的接入阶段，不能让旧实现限定选型。每个本批可达弹窗、子页与必要结果态分别判断；同构数据态可引用既有两轮方案并说明差异。

当前状态、入口发现性、真实事件结果分别判断；缺真实成功事件不单独否决注意引导，图上行动文案也不证明已有新增/未读。未知触发给短条件分支。合并时按区域列视觉首判、交互补充、最终动静结论及变化理由；静态结论也需经过交互复查。先判断主次与表现结构，再映射代码。低频结果有主体和留白时评估合适编排，不把所有过渡限制为微动；不编造角色关节、发奖或到账端点。

方案和交接保存在用户工作区，例如 `evidence/motion/<run-id>/<screen-id>/`，不写插件缓存、技能源码或兄弟工程。分别保留 `01-visual.md`、`02-interaction.md`、`03-merged.md` 或等价记录，不用合并稿回填首判；记录每轮输入路径/hash、显式约束与顾问入口，真实截图hash在接入阶段补充。跨页公共规则存一份，各页引用并补差异。输入或语义变化只重审受影响部分；顾问其他宿主的路径/API规则不替代 LGUI 合同。

## 3. 将方案绑定到 LGUI

在方案旁记录每项表现的真实消费位置：

| 项目 | 实际交接 |
| --- | --- |
| 对象 | 正式包/组件与稳定节点ID，网页和Unity的对应物 |
| 表现 | 触发、目标层/属性、关键值、先后/并行关系、时长/缓动和终态 |
| 实现 | 已核实的 FairyGUI Transition 或目标平台适配器行为；一个属性同阶段只有一个控制者，核对 controller/gear |
| 时间/坐标 | 顾问毫秒与推荐相对尺度，转换后的实际帧/时间单位、fps、逻辑坐标和缩放中心；从当前项目读回核实，不直接把毫秒填进帧字段 |
| 生命周期 | 重播、当前值接管、关闭/回收/失焦、旧回调清理及低动效分支；输入热区稳定 |
| 状态与证据 | proposed、bound、implemented、verified分别记录；缺口和降级写明，代码/包/录屏各自定位 |

已有静态页的节点映射用于接入，不作为提前限定表现强度的理由。无法实现某条推荐时先核实机制/资产缺口，再说明替代与差异。有限点、线、环或已有透明图可在核实的运行时能力上复用；不因缺原特效贴图就自动放弃所有层次，也不虚构通用粒子接口。

正式 Transition 写入、初值和重播见[时间轴参考](transition.md)。在线编辑只走 [lgui-edit](../../lgui-edit/SKILL.md) 支持的会话操作；当前 setDisplayNodeProps 不等于任意时间轴/资源创建API。新增时间轴用编辑器支持的操作，或确认现场编辑器关闭后修改独立离线源，再校验、保存读回、导出发布。不得另开磁盘写者，也不虚构 `motion` CLI 命令。

网页目前可能是手工投影，正式包与网页行为须分别核对；Unity正式发布也不自动生成等价的平台适配器。记录两端的方案、绑定与差异。用户仅要求网页时不扩成Unity构建；要求原生交付时由 [lgui-unity](../../lgui-unity/SKILL.md) 验证实际发布包和原生播放。

业务状态由共享TS/真实事件提交，装饰结束回调不发奖、扣款或伪造网络成功。界面关闭清本页动画与监听，不 dispose整个应用runtime；虚拟条目回收不继承上个item的瞬时效果。

## 4. 正常速度下验收

按 [lgui-verify](../../lgui-verify/SKILL.md) 核对首判、交互复查和合并决定的区域覆盖，再在目标视口正常速度播放代表链路：打开、切换/滚动（本页有时）、提交结果、关闭。看预期动作是否能辨认、主次和节拍是否清楚、正文是否可读、输入是否及时；再验按压释放/取消、开关中断、重开/回收和低动效。只有参数在变化、截图端点或成功编译均不足以宣布方案覆盖或观感通过。

网页和原生按用户要求分别留连续录屏与必要时间测量；序列帧仅支持所观察的顺序和局部状态，无法连续播放时明确观感未验。设计/绑定/运行/视觉分开给结论，不能用浏览器证据推导Unity、真机或目标帧率。先验一条代表过程，再复用已验证公共配方，只复测本页差异和受影响部分。

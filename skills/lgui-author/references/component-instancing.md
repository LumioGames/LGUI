# 组件复用与实例配置

重复单元优先抽成组件。出现三次通常值得检查是否共享结构，但不要强制将语义不同、布局约束不同的节点合并。实例要能预览有意义的文案、图标和状态；动态业务数据仍由共享 TS 提供。

## 实例值与扩展类型

customProperty 的 propertyId 表示属性种类，不是组件内递增序号。多个文本 target 可以都用 Text 的 0，多个图标 target 可以都用 Icon 的 1，以 target 区分。当前固定编辑器 0.2.4 的命令定义/校验仅接受 **0 / 1**；原技能列出的 Color 等更广枚举不能直接当成此客户端可写能力。先查询支持的操作，再预检；拒绝的属性不能通过改磁盘绕开。

示意：两个不同文本节点分别声明属性，实例上覆写相应 target。

```xml
<customProperty target="title" propertyId="0"/>
<customProperty target="description" propertyId="0"/>
```

`extention="Label"` / `Button` / `ProgressBar` 使用其约定子节点，例如 title、icon、bar。改变扩展类型或节点名称时同步检查适配代码的取节点逻辑；不要把别的工程的 componentXxx 自动绑定前缀视为 FairyGUI 本身的要求。

## 离散状态

品级、选中、锁定等可以使用 controller + gear；实例文案/图标可以使用属性覆写。父实例覆写前检查子组件控制器是否可导出，再以目标格式设置页；保存读回后实际切换，确认不是停留在默认页。保持原状态 ID，混合状态参考图应逐实例表达。

按钮遵循目标工程的交互设计，覆盖常态、悬浮、按下、禁用/选中等实际需要的状态。底图切换或叠加高亮均可，不能因来源工程采用某一方式就禁止另一方式。

## 多尺寸实例

| 子节点意图 | 要检查的配置 |
|---|---|
| 随组件填充 | 宽高 relation、显式 size、loader fill；检查 autoSize 是否抵消尺寸变化 |
| 居中且尺寸不变 | center/middle；不要误认为会自动放大 |
| 角标或数值贴边 | 单边 relation；确认缩放后仍可读 |
| 比组件略大的高亮框 | 尺寸关系与负偏移一起验证，避免复合 relation 抹掉偏移 |

宽高 relation 不保证保持宽高比，图片填充模式也要确认。弹窗用本体局部坐标还是全屏容器，取决于宿主布局与遮罩职责；避免宿主与组件重复遮罩。

数据映射逐一对照“标签 → 共享业务 key → 格式化显示”，不能照抄别处调用顺序。未知 key 应报告缺口，不随意借用相似字段。使用 [网页验证](../../lgui-verify/SKILL.md) 与原生验证检查真实实例，不能仅凭 TypeScript 编译通过。

# 简单动效与重播

此册保留原技能的设计经验，未把其原工程“已验证”状态转移到 LGUI。具体 Transition 属性、时间单位、默认 easing 和重复语义以当前工程、编辑器及发布器读回为准；新属性先做最小回路验证。

新界面或交互含义改变时先走[静态界面后的动效顾问](motion-advisor.md)；已有已审方案的参数微调和实现修复直接复用，本册负责将方案接到实际时间轴。顾问毫秒须按实际字段/fps转换并读回，浏览器投影和Unity绑定分别记账。

1. 明确动效所属组件、目标节点 ID、进入/退出触发点及结束状态。
2. 区分瞬时赋值与补间。延迟补间在等待期间也要有明确初值，防止上次播放的残留状态提前闪现。
3. 从已关闭状态再次播放时准备本轮正确初值；播放中打断/重开先保留当前显示值并撤销旧回调，再接到新目标，不先跳回初帧。测试连续播放、播放中关闭、立即重开及controller/gear的结束状态归属。
4. 皮肤/控制器与动效共同修改同一属性时明确谁负责最终状态，避免切页覆盖结束值。
5. 无限循环只用于确实需要的反馈；view 关闭时按生命周期契约停止或解除监听，不能销毁整个共享业务 runtime。

复杂时间轴、声音/路径/震动等未覆盖属性先使用编辑器受支持的操作。在线 Agent 当前不是任意时间轴写入 API；不得生成不存在的命令。通过 [共用编辑流程](../../lgui-edit/SKILL.md)保存读回，再以 [独立验证](../../lgui-verify/SKILL.md)检查实际播放。静态截图只能证明某帧，不能证明时间轴、重播或帧推进正确。

# 旅者背包：复杂功能双端验证

本次按用户授权，在原 Inventory.fairy 背包工程的隔离副本内扩展。原组件、资源 ID、原始网页导出 ZIP 和共享奖励模型保留；新增复杂背包页面与道具资源，不覆盖前轮验证证据。

视觉目标为 art/reference.png：深蓝古铜色面板、六列道具格、右侧详情、分类与搜索、容量与排序。背景和 24 件道具由内置 image_gen 生成；文字、数量、边框、选中态、按钮由真实 FairyGUI 控件呈现。参考图只用于对照，不作整屏贴图代替交互。

共享 TypeScript 管理分类、搜索、排序、选择、消耗品使用、按槽装备和替换、出售与金币、版本化存档恢复。原 Inventory 组合为奖励任务模型，继续验证一次领取。状态失败须原子回滚，非法数量、任务物出售、无效存档均明确返回错误。两端消费同一 IIFE 与 JSON API，平台层只处理输入、资源、布局、存储和生命周期。

采用 FairyGUI 源组件和正式发布产物，独立浏览器走 FairyGUI-dom，Unity 走 FairyGUI-unity + PuerTS V8。生成图集按六列四行等格切片后注册源图片，由工具链分别发布 DOM 散图和 Unity 图集。禁止使用 Unity WebGL、WebView 或编辑器的 Laya 预览代替独立网页。

验收分三层：共享业务自动测试；实际 DOM 页面及原生 Unity 运行时执行同一操作序列比较状态；真实输入和截图核对视觉。分别记录宽屏、390 像素窄屏、资源加载、中文文本输入、滚动、选择与详情、使用/装备/出售、保存恢复、关闭重开、监听与运行时释放。Editor 和 Windows x64 IL2CPP Player 单独报告，未测项不写通过。

窄屏采用四列网格与紧凑详情；整页保留可达的操作区。桌面窄窗口不等于真机。可量测总数据与物理格子数；不把虚拟列表误写成跨语言全量快照成本已经消除。

运行记录、原始失败、截图、资产提示词与哈希均保存在本目录和上级 evidence。生产仓库与同步 sources 只读，不提交、不推送、不上传私有素材。

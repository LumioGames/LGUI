## JSON 边界与绑定覆盖范围

当前调用路径是：

`FairyGUI 原生事件 → InventoryHost → ScriptEnv.Eval<string> → inventoryApp.dispatch(op,argsJson) → JSON 字符串 → JsonUtility DTO → 原生控件更新`。

TS 内部的业务订阅回调也是纯 JS 函数。C# 的 UI 委托注册在 FairyGUI C# 事件上；没有将 JS 函数直接作为 C# UI 委托传入，也没有从 JS 直接调用 FairyGUI 的泛型 API。Item/AppView/AppSession 等 C# 类只承接返回 JSON，不计算筛选结果、状态迁移或金币。

这让本例只需要字符串调用和数据解析，缩小本次互通面。它没有验证通用的 JS→C# 委托、泛型实例、异步/Promise 跨语言回调、托管对象长期持有、全部类型绑定及所有 AOT 签名。即使后续本例 Windows IL2CPP Player 通过，也只扩展该具体路径的证据，不足以宣称完整 PuerTS/FairyGUI TS 绑定或 Android/iOS 全平台通过。

PuerTS 生成物位于 `InventoryUnity/Assets/Gen/Plugins/puerts_il2cpp/`，包括 `PuertsIl2cppBridge.cpp`、`PuertsIl2cppWrapper.cpp`、`PuertsIl2cppFieldWrapper.cpp`、`Puerts_il2cpp.cpp` 和配套头文件。生成入口及完成标记见 [生成日志](../evidence/il2cpp-generate/generate-20261016-085844.log)。其中 `MIGRATION_PUERTS_BRIDGE_GENERATED` 证明该步骤完成；生成代码存在不等于链接、运行或 AOT 行为通过。

## 性能解释及待测项

列表 SetVirtual 已在 Editor 证明物理行少于总数据：30 条时该视口只有 4 个实际行对象，并能滚动复用。它减少的是 UI 对象创建和显示工作。

跨语言 payload 目前仍可能随总道具数量 N 线性增长：原 model.snapshot() 复制全部 items，再过滤 visible；每次 dispatch 将完整 `items` 和 `visible` 一起 JSON.stringify。未筛选时同一道具内容会分别出现在两个数组。C# 再解析两个数组，Host 快照又序列化 DTO 和 rawTsResponse，并在启用证据目录时每 0.25 秒写完整证据。因而“列表虚拟化”不代表跨语言传输、解析、快照复制或日志写入仅与可见行数有关。

调用计时 lastDispatchMs 包含 Eval、完整 JSON 返回与 DTO 解析；lastRenderMs 主要量 C# 绑定，实际行绑定可能随后刷新，另有 rowRender 计数/时间。文件命令往返还包含轮询和至少两个 Unity 帧，不能当纯 UI 延迟。显示对象/图形数不是 GPU draw-call 基准，Tick 数与 Update 相等也不能证明不存在原生或托管泄漏。

真实 Player 的 30/300/3000 条数据、冷启动、跨语言 payload 字节、交互延迟、内存增长和关闭/销毁行为仍需独立记录。压力测试应说明是否开启完整证据日志，避免把日志成本误算成框架固有开销。未来可评估增量响应、按可见范围读取或单独轻量监测，但本轮没有为优化而改写共享业务，也没有用 Node 或 Editor 数字替代 Player 性能数据。

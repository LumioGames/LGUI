# 复杂背包与 Unity 迁移验证

> 版本说明：下文保留最初复杂背包布局的阶段记录，不是当前还原版的最终验收。当前网页入口、修复与运行说明见 [fidelity/README.md](fidelity/README.md)；新正式源/发布见 [发布报告](published/fidelity/publish-report.json)，新 Unity 验收在进行。旧绿报告、旧失败和当前外观应按版本分别阅读。

证据核对日期：2026-10-16。**当前复杂版尚未完成全部验收**：共享业务和双发布通过，Chrome/Edge 初轮功能及 200 次开关通过；随后新增的文字颜色断言在 Chrome 实际失败，DOM 适配正在修复。复杂版 Windows IL2CPP 构建已成功，实际 Player/Editor 验收正在进行，本文暂记待测。后续结果应追加证据，不能用旧绿报告覆盖新发现。

本轮已证明可以沿用同一 Fairy 源工程的资源身份、扩展业务规则，再分别连接独立 DOM 和 Unity 原生 UI。建议仍是**有限采用并继续验证**：资产与纯 TS 业务有实际复用证据；旧 DOM runtime、平台布局/输入/资源适配、生成代码兼容修补都需要维护。参考图已生成并用于还原方向，但这不是像素级复刻，也不能仅凭功能通过认定视觉达标。

复杂源共 39 个文件、34 个资源；原 `Inventory.fairy` 描述文件哈希仍为 `25c87f86ef704e473bcf963fef88fa5b7f96e4b01018454c14e64fc3823e1839`，它保持不变本身不能证明整个新增工程不变，因此同时保存逐文件清单。Main 的展示控件全部为直接 child；静态结构见 [layout.json](published/layout.json)，实际宽窄几何由共享 `scripts/layout.js` 执行。

DOM 正式使用未压缩 Laya profile 的 FGUI 描述文件，复制成旧 DOM 固定读取名 `package.xml`，再按 manifest 将 image ID 映射为散图。`published/dom/` 最终为平铺的 package.xml、manifest.json 与 26 张 PNG；构建时拷入 `web/assets/Inventory/`。这是针对固定旧 DOM 的局部适配，不是 SDK 原生 DOM 发布目标，也没有在运行页加载 Laya 游戏引擎。

Unity 正式发布输出 `Inventory_fui.bytes`（10900 字节）与 `Inventory_atlas0.png`（1846×1768，4866940 字节）。运行资源进入 `Assets/Resources/ComplexInventoryUI/`，由 `UIPackage.AddPackage("ComplexInventoryUI/Inventory")` 加载；同一 `ui://invtest1icxNNNNN` 在 Unity 从图集 sprite 取图，在 DOM 从散图取图。

SDK 边界如实保留：Backend.readResourceBytes 的固定上限为单资源 1 MiB，1,823,210 字节的背景超限；Core NodeIO.readProject 在这里也未填充源 buffer。25 张小图走 revision 检查的 Backend 正式读取；背景由 Core 查询声明文件名，再本地读取源文件原字节并核对哈希。没有改 SDK 限制、图像内容或 runtime。见发布报告的 domReadMethods 与 `published/failure-03-*`、`failure-04-*`。

## 共享业务与平台边界

`shared/model.ts` 新增分类、搜索、稳定排序、选择、堆叠、使用、按槽装备/替换/卸装、出售、金币和 schema 1 存档；默认 24 种图标、26 个栈、容量 30、12480 金币。多出的两件装备实例用于验证身份保留及替换，不把“24 图标”误写成只有 24 个业务实例。失败操作先校验/构建候选状态再提交，负数量、超量、任务物出售和非法存档均须明确失败且原子不变。

原 `验证/prototype/shared/model.ts` 完全未改，SHA256 为 `e3162e7d648a61dd5817918a8e2a753b4899f97fde0a15c124ca2c9a28742cf6`。复杂模型组合真实 `new Inventory(30)` 处理奖励，继续调用原 progress/claim；不是在 C# 重写奖励规则。新复杂业务源码是本轮新增能力，不能将整个复杂背包都称为旧业务原封复用。19 项测试覆盖合法/非法操作、存档恢复、奖励重放限制、250 次开关、DTO 以及过期 disposer；[API 合同](shared/API.md) 给出完整字段与错误码。

浏览器 `web/app.js`、构建 `dist/ComplexInventoryApp.txt`、Unity Resources/ComplexInventoryApp.txt 的实际 SHA256 均为 `3875d59f13ec5517ed711c92d075a3bc7681386d698b20a456d9b2339283af2b`（26651 字节）。[dist/build.json](dist/build.json) 记录原 model 和复杂源码确实进入同一个 IIFE。共享布局 JS 与 Resources/ComplexInventoryLayout.txt 均为 `98be3c0641f2c460a6de8084980eedac795c39309ec6c0f6a15faa34f7d174d7`；[setup-unity](evidence/setup-unity.json) 逐文件核对复制哈希。

两端通过 `globalThis.complexInventoryApp.dispatch(op,argsJson)` 返回 JSON，平台层绑定原生/DOM 控件、输入、资源、存储和生命周期。Unity 使用 ScriptEnv(new BackendV8())，环境跨 UI 开关保留、一次 Update 一次 Tick、Host 销毁才 Dispose。JS 内部业务订阅不直接跨成 C# UI 委托；本例没有证明通用 TS 绑定、泛型或 AOT 委托覆盖。浏览器 localStorage、Unity persistentDataPath 文件是不同存储位置，不自动同步两端存档。

## 已完成的简单背包 Unity 基线

基线与本复杂版分别验收。Unity 6000.6.6f1、PuerTS Core/V8 3.0.3 的 Windows x64 IL2CPP Player 已在 30/300/3000 条数据各通过 22 项严格空错误检查，开关次数分别为 200/20/20；三种规模物理行均为 7，关开保留同一 VM 和状态，退出记录均为一次 Dispose、0 监听与 0 closedCallbacks。见 [baseline Player 汇总](../evidence/player-baseline-summary.json)。30 条进程的退出已确认，但退出码未采集；300/3000 退出码为 0。

这部分通过的是主线程文件命令驱动的真实 Player，不是假设性平台支持，也不是物理点击验证。原 Editor 另有 Unicode 输入、点击、滚轮与实际 390×844 窄屏证据；物理中文 IME 未证实，原生拖拽保持失败/未定位，不能沿用为复杂版通过。详见 [迁移复用边界](../assets-publish/迁移复用边界.md)。

原样 PuerTS 3.0.3 的 IL2CPP 生成模板在此 Unity 版本缺少旧内部 Object::Unbox API。隔离包内只将四个调用替换为公开 C API `il2cpp_object_unbox`，再正式生成/构建；红绿日志、原文件备份和精确差异见 [兼容修补说明](../evidence/compatibility/README.txt)、[验证](../evidence/compatibility/validation.json)。因此结论是“3.0.3 加此局部修补在固定环境实测”，不能宣称原样包完全兼容。更换 Unity/PuerTS 或重生成时须复核维护这四处模板调用。

## 限制与继续条件

- 参考图是视觉方向；字体、格子比例、背景裁切和详情排版需实际截图审查。当前 CSS 黑字已造成真实红测试，修复后应重跑两个浏览器及全部新增断言。
- use 只扣除一份消耗品；装备属性仅供聚合显示，没有战斗生命、法术、毒状态或效果持续时间系统。售卖 UI 当前确认出售一件，协议另支持校验后的指定数量。
- 存档验证提供数据一致性与原子恢复，不提供防作弊、签名、云同步或任意未来版本迁移。刷新网页、退出程序和关闭 UI 的保留范围不同。
- 虚拟网格只减少显示对象。完整 items/visible/rewards 快照、双向 JSON 解析和后台日志仍可能 O(N)；当前复杂版 Host 启用证据目录时约每 0.5 秒写全快照。文件轮询往返、布局绑定时间、GPU 渲染与日志成本要分别解释。
- 基线内存/启动/绑定计数是本机观察，不是长期无泄漏证明或跨框架排名。复杂 Player 性能尚待数据；桌面 Editor/Player 和 headless 窄视口均不能推广到手机。
- 旧 DOM 的图片 fill 是空实现，图集散图映射、文本颜色/布局和输入仍有兼容负担；PuerTS 模板修补、OS 字体可用性及当前本地资源复制路径也需维护。没有把示例 runtime 许可证扩大到所有第三方内容，系统字体未打包外传。

继续条件为最新浏览器视觉回归转绿、复杂 Player/Editor 的同一业务序列与真实输入取证完成，再给整体验收判断。若需要反复修改旧 runtime 才能维持主要视觉与交互，或全量 JSON 不能满足目标数据规模，应单独评估适配成本，不能凭现有功能绿测试宣布低成本迁移已经普遍成立。

复验命令见 [README](README.md)。完整最终截图、运行中进程、退出记录与文件清单由主执行者合并最后一轮证据；本轮文档整理未重生成资源、启动 GUI/进程或改其他文件。

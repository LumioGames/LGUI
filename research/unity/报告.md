# Unity / PuerTS 与官方编辑器核查

核查日期：2026-10-15（America/Los_Angeles；原始日志用 UTC，约 2026-10-16 06:27–06:34）。本报告区分本机观察、固定提交源码、官网说明与建议；没有 Unity 实测通过项。

## 结论

FairyGUI-unity 已提供原生 Unity 渲染与 PuerTS 回调入口，能够作为后续迁移候选。**本次不能证明 DOM 工程产物直接用于 Unity，也不能证明同一业务通过 PuerTS 在 Unity/IL2CPP 正常运行。** 本机未找到可执行的 Unity/Hub、FairyGUI 编辑器及已有 PuerTS 安装，因而按目标文件要求停止 Unity 运行环节；未安装软件、未激活授权、未购买或登录。

发现两个需要纳入采用条件的边界：其一，官方免费社区版可商用制作 UI，但无人值守命令行发布是专业版功能；其二，当前 PuerTS 3.0.3 源码已经推荐 ScriptEnv，旧 FAQ 的 UsingAction/UsingFunc 配方在当前兼容类中为空方法。不要将历史教程直接当成当前 Player 可用性证明。

## 源工程、发布产物与绑定是三个层次

官方[发布说明](https://www.fairygui.com/docs/editor/publish/)允许选发布格式/配置，Unity 描述文件扩展名固定 bytes。FairyGUI 源 `.fairy`/XML 工程可以作为共同资产来源，但必须分别准备 DOM 与 Unity 发布配置并验证格式版本。官方说明也区分描述资源发布与代码生成，不能把“发布资源成功”当成“TS/PuerTS 绑定已生成”。

固定 Unity 源码的 [UIPackage.cs:281–376](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/UI/UIPackage.cs#L281)支持 Resources/自定义 loader/byte[] 等入口；默认加载 `assetPath + "_fui"` 的 TextAsset。其[二进制解析:665 起](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/UI/UIPackage.cs#L665)检查 `0x46475549` 魔数、读取 version 并区分 version>=2。DOM 的 `.fui` 后缀即使改成 `.bytes`，也不能证明资源引用、图集或数据段兼容。

其他子任务已使用 OpenFairyGUI 0.7.0，从[同一个自建 Inventory 源工程](../../toolchain-test/project/Inventory.fairy)正式发布 Unity 产物：[Inventory_fui.bytes](../../toolchain-test/published/unity/Inventory_fui.bytes)与[Inventory_atlas0.png](../../toolchain-test/published/unity/Inventory_atlas0.png)。该源工程另经 Laya 发布与散图 manifest 适配后已由 DOM 实际加载，流程见[工具链 README](../../toolchain-test/README.md)。本机没有可用 Unity，故 Unity 产物尚未实际加载、绑定或渲染，跨端运行兼容性仍未验证。运行库不是 WebView：[NGraphics.cs:100 起](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/Core/NGraphics.cs#L100)创建 Unity MeshFilter/MeshRenderer，说明原生渲染路径确实存在；这不是本次帧率结论。

## PuerTS 接入、委托、生命周期和 AOT

官方[FairyGUI PuerTS 文档](https://www.fairygui.com/docs/unity/puerts/)要求 `FAIRYGUI_PUERTS`，给出声明/胶水生成参考、事件以及 Window/自定义组件扩展方式。固定源码对应存在：

- [Window.cs:39 起](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/UI/Window.cs#L39)：`__onInit/__onShown/__onHide/__doShowAnimation/__doHideAnimation` 均为 Action；Dispose 清空这些字段，窗口 Hide 和 Dispose 是不同操作。
- [GComponent.cs:104 起](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/UI/GComponent.cs#L104)：调用 `__onDispose` 后清空回调；Dispose 会先释放 native tree 和子项。清理函数不宜再访问已销毁子节点。
- [EventListener.cs](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/Event/EventListener.cs#L51)有 EventCallback0/1 的 Add/Remove 重载。适配层应保留同一个函数/委托实例供取消监听，不用新 lambda 去 Remove。
- [GList.cs:13 起](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/UI/GList.cs#L13)有 `ListItemRenderer(int,GObject)` 与 `ListItemProvider(int)`；Dispose 清空 renderer/provider。列表虚拟化在 [1430 起](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/UI/GList.cs#L1430)。`int` 值类型、返回 string、EventContext 引用参数是复验时应单独覆盖的委托签名。
- [UIObjectFactory.cs](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/UI/UIObjectFactory.cs#L15)有 GComponentCreator/GLoaderCreator；[UIPackage.cs](https://github.com/fairygui/FairyGUI-unity/blob/8cc8f214cca79685532eef13372d0a4f74acdf08/Assets/Scripts/UI/UIPackage.cs#L47)有含 out DestroyMethod 的 LoadResource 及异步回调。最小适配应优先用现成 Resources 或一个 C# loader 门面，避免首轮直接把 out 参数桥接当成已可用。

**当前版本断层有源码证据。** [PuerTS JsEnv.cs:31](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/unity/upms/core/Runtime/Src/JsEnv.cs#L31)将 JsEnv 标为过时并指向 ScriptEnv；其 [172–207 行](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/unity/upms/core/Runtime/Src/JsEnv.cs#L172)的 UsingAction/UsingFunc 方法体为空。同 commit 的 [FAQ:77 起](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/doc/unity/zhcn/faq.md#L77)仍介绍旧注册方式。这只能证明文档与实现不能直接混用，不能由此推断 PuerTS 3 的所有委托都失败。

当前 [UnityMenu.cs](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/unity/upms/core/Editor/Src/Generator/UnityMenu.cs#L25)仍有 IL2CPP Reflection / Static Wrapper / Minimal Bridge、C# Static Wrappers 与 Link.xml 生成功能，[StaticWrapperMenu.cs](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/unity/upms/core/Editor/Src/Generator/StaticWrapperMenu.cs#L29)确实读取 Binding/Filter 配置。生成存在不等于 FairyGUI 所需具体委托、闭合泛型、继承扩展、枚举、out 参数和剪裁都已覆盖。泛型调用应建立小型显式门面/固定闭合类型清单，分别在目标 Player 检查；不要自动绑定所有导出类型后就标 AOT 通过。

全局脚本宿主应独立于单个窗口，主线程每帧只调一次 `ScriptEnv.Tick()`；[PInvoke ScriptEnv:303 起](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/unity/upms/core/Runtime/Src/PInvoke/ScriptEnv.cs#L303)与 [IL2CPP ScriptEnv:222 起](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/unity/upms/core/Runtime/Src/IL2Cpp/ScriptEnv.cs#L222)都有 Tick 和 Dispose 路径。关闭窗口只撤订阅、取消/失效化待完成操作和释放 UI；应用退出才销毁脚本宿主。这是设计建议，尚无 Unity 运行证据。资源异步完成后须检查窗口 generation/closed 标记，不能让延迟回调写入旧 view。Task 到 Promise 的具体桥接与异常传播同样待测。

## 官方编辑器与许可边界

官方[插件文档](https://www.fairygui.com/docs/editor/plugin/)允许 Lua/TS/JS，列出资源、舞台属性和发布扩展入口；TS 要转成 JS，宿主是 XLua/PuerTS。它提供正式扩展路径，但没有在本机启动编辑器验证保存、Undo/Redo、revision 冲突或可视化。磁盘 XML 工具也不能默认与桌面未保存会话同步。

官方[购买页](https://www.fairygui.com/buy/)将社区版列为免费、支持商业 UI 制作，将命令行发布列为专业版增项。这意味着本次不能假定官方 CLI 自动发布免费或已获授权；也不应通过修改授权检查来解决自动化问题。手动社区版发布、正式插件操作和 OpenFairyGUI 自主发布应各自核查能力与许可，不相互替代验收。

## 最小复验步骤与采用门槛（未执行）

1. 用户准备可用授权的 Unity 编辑器与测试所需构建模块，报告版本、模块和授权状态即可，不保存许可正文。独立新建 `验证/unity-smoke/`；不要打开/升级生产项目。2022.3.17f1c1 只是本次上游示例基线，实际选择必须连同目标平台验证。
2. 复制本次**同一个自建 UI 源工程**，保留 package/component ID，另建 Unity 发布配置。产出 `_fui.bytes`、图集等 Unity 资源到隔离项目，并列明与 DOM 发布配置的差异及 SHA256。先由 C# 用 UIPackage 加载，确认控制器、动效、中文字体和资源引用。
3. 接入本报告固定 FairyGUI runtime；PuerTS 必须锁定 core 与 backend 的匹配发行包或自行构建的同 commit 组合，记录哈希。不能把只下载 core 源码当成 native backend 已可用。开启 FAIRYGUI_PUERTS。
4. 原封不动编译浏览器验证的纯 TS 业务模块为 PuerTS 可加载模块；仅换 UI port。Unity port 负责大小写 API、事件 Add/Remove、列表 renderer、资源、布局和 tween；共享模块不出现 DOM、CS、UnityEngine。不要复制业务逻辑到 C# 作为“复用”。
5. 按该固定 PuerTS 版本生成声明、绑定与 AOT/Link.xml 配置，显式覆盖 EventCallback0、EventCallback1(EventContext)、ListItemRenderer(int,GObject)、ListItemProvider(int)、GComponentCreator、Action 及真实使用的闭合泛型。验证删除监听后回调计数为零。当前 3.0.3 不使用空 UsingAction 方法作为 AOT 已注册证据。
6. 全局宿主只建一次、只 Tick 一次；open→filter→claim→close 连续执行至少 50 次。断言状态不被重置、单次领取只触发一次、关窗后异步结果不改旧对象、旧事件不再回调、全局运行时仍可打开下一窗口。分别记录 UI 节点数、托管/原生内存、监听数和每帧 Tick 次数。
7. 先测 Editor，再构建实际目标 IL2CPP Player；对反射剪裁、泛型/委托、异步任务异常、输入法、字体、图集和渲染分别留证。Editor 通过只能标 Editor 通过。Android/iOS 真机结论需各自产物与设备，不由桌面或 Unity WebGL 代替。
8. 将纯业务事件/状态快照与浏览器同操作轨迹比对；记录冷启动/首屏、列表总量与可见实体数、局部更新、滚动与多次开关后的原始数据。没有跨平台相同条件，不给性能排名。

继续条件：同源资源在两端发布/加载、同份业务经两 port、上述生命周期与目标 Player 验证均成功，并解决实际分发涉及的第三方/素材许可。止损条件：为了 DOM/Unity 补齐核心控件或格式需要长期分叉、业务被迫分成两套、关键 Player 委托/AOT 无可靠解法，或授权/自动化成本超出项目接受范围。届时再评估 OneJS V3 是否实际绕过具体阻塞。

# OpenFairyGUI 与网页编辑器核验

核查日期：2026-10-15（用户时区 America/Los_Angeles）。建议**有限采用 OpenFairyGUI 作为可审查的工程/事务工具链；暂不把当前网页编辑器当作完整可靠的 Agent 同会话编辑入口**。正式 Node SDK 闭环成立，DOM 发布需新增适配，Unity/PuerTS TS 代码生成缺口真实存在。网页实际发现一个可稳定复现的文本 Inspector 命令错误，已经定位而未修复。

## DOM与Unity发布断点

当前 [ProjectType枚举](https://github.com/OpenFairyGUI/OpenFairyGUI/blob/6e29ee2e8a4cf557579f3d374450f99d06152985/packages/core/src/constants.ts#L389) 没有DOM目标；[publishBrowser](https://github.com/OpenFairyGUI/OpenFairyGUI/blob/6e29ee2e8a4cf557579f3d374450f99d06152985/packages/functions/src/adapters/web/publish.ts#L9) 只允许layabox。Node流程可发布Unity，不能因此称为原生DOM exporter。

BinaryWriter的 [image分支](https://github.com/OpenFairyGUI/OpenFairyGUI/blob/6e29ee2e8a4cf557579f3d374450f99d06152985/packages/core/src/io/binary-writer.ts#L345) 把file写为null，图像由atlas/sprite重建。旧FairyGUI-dom直接读image.file，需要散图；单纯改扩展名无效。此次新增 `export-dom-images.mjs` 用正式Backend完整模型与revision读取primary bytes，复制真实未压缩Laya二进制为DOM固定请求名 package.xml，生成imageID→散图manifest；消费端在createObject前通过公开PackageItem.file应用映射。它是当前小样本适配，无二进制改写，无runtime fork；分支、多分辨率、九宫格、电影剪辑等并未因此获证。

同源工程分别发布Laya与Unity配置。修改后描述均3451字节，但PNG分别155/147字节，Unity单图直接输出与Laya图集口径不同；不能以描述大小相同推断目标完整兼容。真正DOM交互验收由主报告给出。

绑定生成使用 [supportsCodeGenerationLane](https://github.com/OpenFairyGUI/OpenFairyGUI/blob/6e29ee2e8a4cf557579f3d374450f99d06152985/packages/functions/src/codegen-settings.ts#L78) 与 [TS变体选择](https://github.com/OpenFairyGUI/OpenFairyGUI/blob/6e29ee2e8a4cf557579f3d374450f99d06152985/packages/functions/src/codegen-render.ts#L53)。实际三次发布：Unity空codeType生成4组件类+Binder共5个.cs；Unity `codeType=TypeScript` 只发布资源并warning skipped，无.ts；Laya生成5个.ts，引用fgui。后者不能直接冒充Unity/PuerTS的CS命名空间/委托/生命周期绑定。原始manifest、warning与生成文件在codegen-probe与toolchain-codegen.json。

## 网页会话与错误根因

网页 [BrowserLiveSessionBridge](https://github.com/OpenFairyGUI/FairyGUI-Editor-Online/blob/45f0bef93bb16d507552b673ace6d5af417a8a0f/src/editor/services/BrowserLiveSessionBridge.ts#L651) 自建BackendRuntime，用browser workspace文件系统打开工程；apply/save带当前revision。 [EditorCommandAdapter](https://github.com/OpenFairyGUI/FairyGUI-Editor-Online/blob/45f0bef93bb16d507552b673ace6d5af417a8a0f/src/editor/commands/EditorCommandAdapter.ts#L98) 要求live revision与编辑器一致，保存checkpoint与undo/redo历史由宿主维护。磁盘stdio是另一runtime，不共享这份会话内存。ZIP导入后用原生UI移动title到35并保存浏览器；刷新后保持35，磁盘通过正式SDK再查询仍34，是本轮实际隔离证据。未授权任何目录句柄，没有写回用户工程，没有向在线站点上传文件。

网页修改文本时， [InspectorController](https://github.com/OpenFairyGUI/FairyGUI-Editor-Online/blob/45f0bef93bb16d507552b673ace6d5af417a8a0f/src/editor/ui/InspectorController.ts#L167) 同时生成props.text等单字段和props.textProperties整组；0.2.4 [preflight](https://github.com/OpenFairyGUI/OpenFairyGUI/blob/413914fc30e09867dc355343760b36b7f1ca7d90/packages/core/src/uam/transaction-preflight.ts#L962) 拒绝混用。实际完整诊断为 `textProperties cannot be combined with individual text property overrides`，发生于snapshot预演、Backend apply前；失败保持dirty=false（首次）。Node分别用0.2.4包与checked-in浏览器bundle重放：text-only、full-textProperties-only、position-only都通过，混合载荷都被同因拒绝。因此证据指向Inspector映射错误，不能泛化成所有0.7工程与旧版本不兼容。临时只扩大错误显示以取证，已恢复源码，未修功能。

现有 [BrowserPluginHost v1](https://github.com/OpenFairyGUI/FairyGUI-Editor-Online/blob/45f0bef93bb16d507552b673ace6d5af417a8a0f/src/editor/runtime/BrowserPluginHost.ts#L157) 只允许当前选中节点的finite position.x/y写操作。它不是完整Agent/MCP入口；未提供本轮三类修改的同浏览器共享revision闭环。若采用，需加受控桥，让Agent直接调用同一会话并处理版本、授权、预检、保存、undo及UI失效刷新，避免磁盘与浏览器双主状态。

# OneJS V3 固定版本备选路线核查

核查日期：2026-10-15（America/Los_Angeles）。本报告只核查 OneJS 备选，不建设第二套完整 UI，不替代本轮 FairyGUI 实证报告。证据类型为**固定源码、官方文档及本地只读核查**；没有运行 Unity、OneJS、PuerTS 或其浏览器容器，没有性能实测。

## 结论

**保留 OneJS V3 为需要专项研发的备选，当前证据不足以建议转向。** 当前主线已经提供 React 19 到 Unity UI Toolkit 的原生渲染、构建、预览、事件与资源生命周期，但不直接满足本任务的两项硬条件：独立浏览器不带 Unity，以及 Unity 业务统一运行于 PuerTS。前者需要新的 DOM 后端；后者需要改宿主、互通协议与部分 C# bridge。它们均不是改配置即可获得的能力。

尤其不要将现成 OJPlay 作为“纯网页后端”：官方明确说明，浏览器里的 cart 使用共享的 Unity/OneJS container，`ojplay run` 也在本地 Chrome 使用这个容器。[OJPlay 官方说明](https://play.onejs.com/docs/start)。现有 WebGL 插件同样经 Unity WASM/IL2CPP 工作，[架构源码说明](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Plugins/WebGL/README.md#L9-L43)。这些形式均不能计入本任务的独立浏览器通过项。

V3 的 TSX 源码适合 Agent 审查与修改，React 组件结构也可成为跨平台共同源。但普通网页组件、DOM ref、完整 CSS、Unity 纹理与 VisualElement ref 都不能自动互换；应先限定共同组件、样式和事件合同，再验证实际复用。**不建议退回 V2**；本次未检出、未运行历史分支。

## 当前宿主、互通和生命周期

### 当前实现：自有 QuickJS，不是 PuerTS

`JsHost` 集中创建、运行、Tick、onPlay/onStop 和重建，但 `Bridge` 类型是具体的 `QuickJSUIBridge`，创建时直接 `new QuickJSUIBridge`，并通过 `QuickJSNative.RegisterObject`、`__csHelpers.wrapObject` 注入 `__root` 与 `__bridge`。它是可用于重构的集中点，**还不是可插拔引擎接口**。[JsHost L27–77](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/JsHost.cs#L27-L77)

`QuickJSUIBridge` 构造时直接创建 `QuickJSContext`；后者创建 `qjs_create` 原生上下文并加载 `QuickJSBootstrap.js`。平台层在 Editor/Standalone 链接 `quickjs_unity`，在 WebGL 链接 Emscripten `__Internal`，让 JavaScript 在浏览器引擎里执行，UI 依然属于 Unity。[bridge 构造](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/QuickJSUIBridge.cs#L180-L198)、[上下文构造](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/QuickJSContext.cs#L50-L70)、[平台选择](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/QuickJSNative.cs#L14-L37)

### 换为 PuerTS 至少需要的改动

| 接口面 | 固定版耦合证据 | 必须处理的工作（设计推断，未实现） |
|---|---|---|
| 宿主与启动 | `JsHost.Create/Run` 使用具体 bridge、句柄与 bootstrap | 提取运行时生命周期接口，由 PuerTS 宿主提供 eval、函数调用、错误/源映射、Tick、挂载/卸载；让全局业务 env 独立于页面根 |
| 对象与树操作 | reconciler 读取 `__csHandle`；`NodeBridge` 从 QuickJS 表取对象 | 避免把 PuerTS 对象当作 OneJS 句柄；改为真实对象方法，或实现独立的元素 ID 注册表与 NodeBridge。虽然树操作有无句柄 fallback，事件、行 portal 等仍依赖句柄，不能据此认定整体兼容 |
| 样式与参数转换 | `StyleBridge.ApplyStyles` 要求 `Dictionary<string, object>`；转换仍调用 `QuickJSNative.ConvertToTargetType` | 固定明确的数据合同/DTO 或 JSON 批量接口，替换转换器；复测枚举、null 清除、颜色、长度、transform、资源引用，不假定 PuerTS 自动得到同样字典 |
| 事件与委托 | `__eventAPI`、callback handles、capture/bubble 与 C# per-element 回调 | 保留 React 事件层语义，改 C#→JS 回调实现和资源 ownership；验证同一 handler 解绑、停止传播、捕获、焦点、异常、销毁后异步回调 |
| Promise 和调度 | native Task 转 taskId，`Tick` 排队解析，再执行 microtasks | 用目标 PuerTS 版本的异步/调度合同适配；只保留一个全局 Tick，避免重复泵队列和 React scheduler 饥饿 |
| 构建与 AOT | bridge 类型、反射、link.xml、类型生成均为现有运行时服务 | 固定 PuerTS/后端版本和代码生成策略；验证静态 wrapper、委托和值类型、泛型、linker stripping、IL2CPP Player，而非只在 Editor 编译 |

具体证据：[树操作与 fallback](https://github.com/Singtaa/onejs-react/blob/498ee4b433d43dd10d01dc1ca70dc49aeaeb1ccf/src/host-config.ts#L650-L690)、[NodeBridge 句柄解析](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/NodeBridge.cs#L45-L62)、[StyleBridge 参数](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/StyleBridge.cs#L40-L84)、[样式转换](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/StyleBridge.cs#L255-L295)、[Task 合同](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/QuickJSNative.Tasks.cs#L9-L31)、[Tick](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/QuickJSUIBridge.cs#L550-L590)、[link.xml](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Plugins/link.xml#L1-L59)。

PuerTS 当前官方文档已介绍 3.0 的 `ScriptEnv + Backend`，并将旧 `JsEnv` 标为旧语法；其 Task 示例使用 `puer.$promise`。因此接入时必须先固定实际 PuerTS 包版本，不能把旧 JsEnv 代码、OneJS 自动 Task→Promise 与新文档混成一个已验证方案。[官方启动文档](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/doc/unity/en/tutorial/runJS.md#L1-L25)、[官方互通文档](https://github.com/Tencent/puerts/blob/0ac7d2f1943e0f7bca9860ceab592ab390e6719b/doc/unity/en/tutorial/js2cs.md#L166-L199)。这两项仅作在线文档核验，引用文档固定在 master 提交 `0ac7d2f1943e0f7bca9860ceab592ab390e6719b`，没有选择或运行 PuerTS 包。当前官方文档的命名空间写法本身也有新旧差异，应以将来实际锁定的程序集/API 为准。

### UI 关闭与全局业务 env 的边界

现有 `JsHost.Recreate` 是 Stop→Create→Run→onPlay，销毁上下文会丢失其中的 JS 状态；`JSRunner.OnDestroy` 会 Dispose，重新启用也走重建路径。[宿主重建](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/JsHost.cs#L137-L164)、[runner 重建](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/JSRunner.cs#L979-L1024)、[runner 销毁](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/JSRunner.cs#L2018-L2027)。所以页面关闭应执行 root/component unmount 或隐藏，保持应用级 env 所有者存活；不能把每次页面开关实现成销毁并重建全局宿主。

现有 teardown 已有值得保留的设计：在 env 仍存活时先运行 React cleanup、释放上下文拥有的资源、注销事件/样式/socket，最后才销毁 env 和必要的共享表；renderer 同步 unmount 并 flush passive effects，再释放图片缓存。[C# teardown](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/QuickJSUIBridge.cs#L337-L397)、[React teardown](https://github.com/Singtaa/onejs-react/blob/498ee4b433d43dd10d01dc1ca70dc49aeaeb1ccf/src/renderer.ts#L55-L80)、[同步 unmount](https://github.com/Singtaa/onejs-react/blob/498ee4b433d43dd10d01dc1ca70dc49aeaeb1ccf/src/renderer.ts#L118-L147)。这是源码能力，不是本次泄漏测试通过。

## 独立浏览器后端和共同 UI 合同

`onejs-react` 的 `TYPE_MAP` 直接构造 UI Toolkit 的 VisualElement、TextField、ListView 等，没有 HTML element 后端入口；图片模块在导入时就访问 C# ImageConversion，并通过 System.IO、UnityWebRequest、Texture2D/VectorImage 管理图片。直接把现有 React 包装进普通网页仍会遇到 CS/Unity 依赖。[组件工厂](https://github.com/Singtaa/onejs-react/blob/498ee4b433d43dd10d01dc1ca70dc49aeaeb1ccf/src/host-config.ts#L268-L286)、[图片模块及路径](https://github.com/Singtaa/onejs-react/blob/498ee4b433d43dd10d01dc1ca70dc49aeaeb1ccf/src/image-cache.ts#L20-L88)。

建议的最小改造边界是**同一份业务与页面组合 + 平台 UI 门面**：浏览器用 React DOM 的组件实现，Unity 用修改后的 OneJS V3 renderer 实现。先只承诺 View、Text、Button、Input、Scroll、Image、Modal、必要的虚拟列表与少量 token；门面包通过构建 alias/条件导出选择平台。另一种方案是把现有 host-config 抽成通用 backend 再实现 DOM，这会直接维护更多 reconciler 细节，只有确需保留全套 onejs-react 内部语义时才值得采用。二者都未在本轮实现。

| 领域 | 可能共享 | 必须适配或限制 |
|---|---|---|
| 业务与 React 结构 | 纯 TS 状态、奖励规则、筛选、资源逻辑 ID、无宿主依赖 hooks、门面组件组合 | 禁止共享业务引用 DOM、UnityEngine、`CS`、VisualElement ref；依赖宿主的 hooks 从门面注入 |
| 组件 | 常见容器、按钮、文本、输入、弹窗可保留共同 props | UI Toolkit 的 `text` props、`e.value`、focus、pointer capture、disabled 和 ref 方法映射；不直接透传 DOM props |
| 样式 | 颜色/间距/字号 token、共同 flex 子集、共同布局规则 | USS 不等于 CSS。V3 指南列出 grid/gap/z-index/box shadow 等限制；浏览器便利能力不能溢出共同子集。字体 metrics、换行、缩放、滤镜要分别验收 |
| 事件 | 语义动作 `onPress/onValueChanged` 及统一的指针、键盘数据 | 捕获/冒泡、输入/change 时机、IME composition、滚轮单位、pointer capture、触摸/游戏手柄。事件接口应规范化后才可共享 |
| 列表 | item 数据与行 React 内容 | 当前 ListView 行 portal 以 C# 句柄标识，池化由 UI Toolkit 管理；浏览器需自己的虚拟化及稳定 ID，不把总数据条数等同于创建节点数 |
| 资源 | 自制 PNG/SVG、字体许可明确的字体、逻辑路径、引用清单 | Web URL/缓存/Abort 与 Unity TextAsset/StreamingAssets/Texture2D 的路径、异步、释放、打包规则；材质、Shader、RenderTexture、Pack Unity Object 不能直接共享 |
| 生命周期 | 挂载/卸载、订阅 disposer、异步取消与页面状态合同 | 业务 env 常驻，单页面 cleanup；热重载与页面关闭分别处理；不要使浏览器原生 timer 与 Unity Tick 同时驱动同一应用 |

补充证据：[样式转换合同](https://github.com/Singtaa/onejs-react/blob/498ee4b433d43dd10d01dc1ca70dc49aeaeb1ccf/src/style-parser.ts#L1-L17)、[V3 样式边界](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/AGENTS.md#L98-L107)、[事件 props](https://github.com/Singtaa/onejs-react/blob/498ee4b433d43dd10d01dc1ca70dc49aeaeb1ccf/src/host-config.ts#L323-L374)、[列表 ownership](https://github.com/Singtaa/onejs-react/blob/498ee4b433d43dd10d01dc1ca70dc49aeaeb1ccf/src/rows.tsx#L7-L20)。另有版本不一致值得注意：React 包 README 仍称 mouse/input/transition 没有 runtime dispatch，但固定 OneJS C# 已注册这些事件。[当前 per-element handlers](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/QuickJSUIBridge.cs#L1079-L1124)。本报告以匹配版本源码为准，并仍将 IME/交互行为列为未测试。

## Agent 与人工编辑闭环

已有链路为：TSX/USS 文件→typecheck/build→app.js.txt→Unity 编辑/运行预览→日志/截图。官方给出 headless `ProjectSetup.Initialize` 入口和 Unity MCP 的 eval、Play mode、日志、Game view 截图工具；源码会在初始化失败时抛异常，并在 batch mode 保存 scene/assets。[官方 Agent 安装说明](https://onejs.com/docs/ai-setup)、[初始化与失败处理](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Editor/ProjectSetup.cs#L37-L68)。这项能力有利于 Agent，但运行时仍需要 Unity；本次没有安装额外 MCP。

运行时有 `UIDebugger` 的树与 class/type 查询入口，可用于把截图定位到元素。[查询工具源码](https://github.com/Singtaa/OneJS/blob/538026e34ad843c285120ceea7af4cc9f9af7abf/Runtime/Utils/UIDebugger.cs#L13-L102)。它不等同于已验证的工程事务系统。本次未找到并验证“可视化改 VisualElement 后自动回写对应 TSX、保留表达式”的接口；也未验证稳定组件 ID、revision 冲突、原子保存、撤销/重做与无关内容保护。因此人工看预览成立的源码入口，不能推广为人工拖动调整后可靠持久化已通过。

若继续，需要补一个围绕**源文件**的可恢复协议：稳定 UI ID→源位置映射、预期文件 hash/revision、目标缺失明确失败、typecheck/build 预检、原子写入/失败回滚、前后 diff、构建错误结构化、截图与交互断言、重新打开确认。普通文本编辑可借本地版本控制审查；视觉编辑如果是硬需求，应做门面属性面板/有限声明 schema，而非承诺任意 TSX 都可双向可视化编辑。这是新增工具工作，不宜隐藏在“支持 AI Skill”一句中。
